From clone to your first scored run

Six steps. Everything here is free, and the last step only prints a command. Keys stay in your shell and are never stored. Nothing on this page can start a paid run.

This page is being served statically, so the harness is not reachable.

Clone the repo, then run ./spring-evals serve and open http://localhost:4173/onboarding.html. Each step below explains what it checks; the buttons stay disabled until then.

    Every step reads the current state when you press its button, so you can come back and re-run any of them.

    01

    Environment

    Agents and the judge run in Docker containers from one pinned image. The harness itself needs a JDK.

    02

    Agents

    Each agent is a CLI and model pair from agents/*.json. Pick the ones you have accounts for. The selection is saved to a gitignored local file and never changes how an attempt is measured.

    03

    Credentials

    Each config references keys as ${VAR}. The doctor checks that the variables are set in your shell and which billing source they select. It never prints values and never stores anything. Add the export lines to your shell profile, restart the terminal, and re-check.

    04

    Prove it

    Validate one eval: the broken project must fail the hidden tests and the reference solution must pass them, both inside containers. No model is involved and nothing is spent. The first run builds the benchmark image and downloads dependencies, so allow several minutes.

    
        
    

        
    
          
    
            05
            
    Estimate
    
          
    
          
    Projected spend for the enabled agents: every sample runs, so it is evals times samples times the per-sample estimate in each config. Subscription-billed agents draw on plan quota instead of dollars. This is a planning number, not a billing guarantee.
    
          
    
            
            
            
            
            
          
    
          
    
        
    

        
    
          
    
            06
            
    Your run command
    
          
    
          
    Paid runs are started from the terminal by a person, never from this page. The harness refuses to spend without both flags below, and it stops before the cap would be exceeded. The cap here is the projection from step 5, rounded up.
    
          
    
          
    
            
            
          
    
          
    After the run, ./spring-evals report rebuilds the leaderboard and the run appears under Runs. Write a short findings note to results/runs/<run-name>.notes.md and re-run report; it merges into the run log.
